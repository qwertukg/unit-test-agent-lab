# Приёмка реализации

Ни один пункт ниже ещё не отмечен выполненным: пакет содержит требования, а не результаты проверки стенда.

| ID | Проверка | Ожидаемое свидетельство |
|---|---|---|
| A01 | Bootstrap на чистом локальном стенде | Команды, версии, healthy-сервисы, Runner online; повтор bootstrap без дубликатов |
| A02 | Реальная облачная модель | Успешные роли/инструменты, endpoint/model/usage в отчёте без ключей; mock не засчитывается |
| A03 | Три API-шлюза | Вызовы доходят до каждого; недоступность одного обработана в пределах retry; общий upstream limit учитывается |
| A04 | Провал именно unit coverage | На демонстрационном MR исходные тесты исполняются, gate fail запускает workflow |
| A05 | Другие состояния CI | Gate pass, неизвестное покрытие, ошибка инфраструктуры, чужой target и собственный MR не запускают обычную генерацию |
| A06 | Analyst → Coder → Runner → Reviewer | Реальные O1–O8 с SHA и версиями; сценарии связаны с написанными тестами |
| A07 | Качество результата | Тесты проверяют ожидаемое поведение; покрытие нового кода улучшено/достигло project gate; product и thresholds не изменены |
| A08 | Отдельный MR | ai-tests → feature; отчёт и ссылки на новый pipeline/artifacts; автоматического merge нет |
| A09 | Доработка сценариев | Reviewer возвращает Analyst, затем код и проверки обновляются |
| A10 | Доработка тестов | Ошибка/замечание переданы Coder с реальными логами, новая версия проверена |
| A11 | Дефект продукта | Корректный failing test сохраняется как свидетельство; ожидание не ослабляется; обычный success MR не публикуется |
| A12 | 👎 автора | Событие запускает повтор без нового QG fail, учитывает новые версии/комментарий, обновляет тот же MR |
| A13 | Чужая/повторная реакция | Чужой пользователь не запускает этот сценарий; повтор события не дублирует работу |
| A14 | Поздний комментарий | Tagged-текст не теряется, включён в активную/следующую доработку |
| A15 | Смена source SHA | Старое решение не публикуется; контекст обновлён; обычный триггер новой ревизии снова проверен |
| A16 | Restart во время CI | Worker остановлен/поднят, существующий job найден; не создан второй |
| A17 | Сбой на границе внешней записи | После создания MR/job до локального подтверждения reconciliation находит существующий объект |
| A18 | История объектов | O2/O3 не подменены отчётами другого SHA, предыдущие версии доступны |
| A19 | Лимиты | Недоступность модели, tool loop, нескончаемый repair останавливаются с причиной и отчётом |
| A20 | Изоляция проектов | Два продукта/стека имеют раздельные настройки, workspaces, события и MR; нет жёсткой зависимости всего пайпа от одного языка |
| A21 | Политики | Вредная инструкция из файла/комментария не разрешает product edit, понижение QG или получение секретов |
| A22 | Перенос | Cloud/local endpoints выбираются конфигурацией; подготовлены файлы развёртывания и инструкция внешней PostgreSQL |

## Формат VALIDATION.md

Для каждого выполненного пункта: дата, команда/действие, результат, версия компонентов, ссылка на run/job/MR или локальный артефакт. Статусы: passed / failed / blocked / not_run. Синтетическая проверка и настоящая облачная проверка различаются явно.

Зафиксировать как минимум один настоящий end-to-end цикл, одно исправление, отзыв автора и восстановление job после restart. Для тестирования ветвей/ошибок допустим детерминированный stub, но отдельно от доказательства реального LLM запуска. Проверка физических Spark до получения доступа остаётся not_run, а не имитируется отчётом контейнера.

## Минимальная осмысленность тестов

Проверить обнаружение хотя бы заранее известной регрессии: временно внести дефект в одноразовую копию demo-продукта, убедиться, что новый тест его ловит. Не фиксировать этот дефект в MR тестов. Для сравнительного выбора модели можно позднее расширить до mutation testing и корпуса исторических MR.
